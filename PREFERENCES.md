# Preferences port

The seven pages contain working settings. Disabled buttons indicate a missing selection or dependency, such as bitrate being editable only for MP3. Audio forwarding adds foreground-app/whole-PC sources, independent volume and optional voice muting, plus manual toggle/hold/stop controls. Two additional Special Hotkeys provide toggle and push-to-forward; they do not replace the 44 original actions. Forwarding starts off at each launch, and configuration changes use Apply while the forwarding controls take effect immediately.

Sound shortcuts default to a persistent sound ID and keep playing that sound after changing categories or sorting. **Same hotkeys in all categories** is an opt-in row mode: shortcuts follow the visible row in the selected category. Its tooltip explains the distinction. Existing preferences retain their chosen mode; switching off row mode exposes the per-sound assignments.

Apply persists without closing, Cancel discards subsequent draft edits, Reset restores defaults, and numeric fields validate before changing the running application. The extra Uncategorized tree row has been removed. The executable, window and tray use the newly drawn red play/audio icon; its editable vector is `app/assets/app-icon.svg` in the source workspace.

Volume sliders fill the elapsed side in the toolbar accent color. Edit category provides the 28 observed palette entries, with gradient color swatches in the list and the selected item; saved colors from earlier previews remain selectable.

Interface now includes the compact response graph beside Volume slider works linearly. The straight/curved preview follows the actual linear/squared gain mappings. Devices uses tall microphone rows, separate endpoint/controller labels, the Windows default-device badge, compact Boost/Status columns, colored status, a status-help button, shield Repair button and square Refresh button. The footer stays visible as the list resizes. Its row menu has Set boost, Set setup mode, Windows Audio Preferences and Restart Win-Audio; the blank-area menu omits the device-specific commands. Restart asks before interrupting audio.

Recorder aligns every value in one column, shows the effective default folder (`<application data directory>\recordings`), uses an inline normalization dB dropdown and displays the recording limit as minutes/seconds. Bitrate and normalization targets grey out with their dependencies. Editor greys/disables the path, Browse and parameters together when Use external sound editor is unchecked, preserving their values.

Set setup mode exposes this mixer's four existing installation slots (PostMix, Stream, Mode and Endpoint). Applying a different slot restores the previous vendor effect, preserves originals across repeated mode changes and updates the backup atomically. These slot names and the setup dialog are specific to this implementation; the original's driver-dependent numbered mode list and live setup-test dialog have not been reproduced. Thirteen fixture checks exercise original-effect chaining, repeated mode changes, repair and invalid-backup rejection without changing Windows settings. Live mode switching remains unverified.

The speaker slider applies gain only to this player's PCM buffer; it does not set Windows endpoint/master volume or other applications' session volume. The separate Reduce volume of other applications setting deliberately invokes Windows communications ducking only when enabled and a sound is playing. Tests do not start this communications stream by default.

Clicking the volume track moves to the pointed value; keyboard/page steps are bounded. Play selects the first visible sound if no row was selected. Startup no longer aborts on an unavailable remote pipe, and playback failures display an inline message. A busy microphone mixer identifies the other running instance rather than suggesting device repair.

## Evidence and validation

Reference: the supplied Soundpad 4.0.30 executable, SHA-256 `45C0B385E633D8EBA46C79928914227779C33FBA322181B799B367D192C73CF4`, runtime screenshots, native control text and combo contents. Retained workspace evidence is in `../analysis/gui-evidence/preferences-*`, `../analysis/preferences-hotkey-action-labels.json` and `../analysis/preferences-hotkey-constructor-0x140200760.asm`. The hotkey constructor at `0x140200760` establishes the 44 actions and their defaults. These are ordinary native/static and runtime observations; no REA server or native decompiler was available in this session.

Audio behavior was also checked against the original application's configuration manual. This is an independent implementation; it does not recover the original source code or establish identical output for every file and application.

Automated checks cover audio arithmetic, per-channel normalization, activation and karaoke routing, all export formats, actual communications-stream startup, hotkey/rule logic, persistence, original value limits, and live interface changes. GUI checks include navigation, Apply/Cancel, theme, zoom, sorting and French translation. Preferences buttons have rounded corners. Help callouts have the observed blue information icon, title and description. The Audio page includes the observed measurement icons, fixed-adjustment decibel dropdown, symmetrical headphones preview, integer delay spinners, and disabled/unselected volume-reduction choices. Voice capture starts/stops inline, and fixed measurement displays completed results without opening a progress window. The Hotkeys page uses blue action icons, left-aligned action headers, two horizontal modifier rows and selection-dependent Auto Keys buttons. Timing/application defaults are available in the Auto Keys editor. Spinner values and dropdown choices are verified through Apply and persistence. The native suite exercises independent endpoint producers and actual APO callbacks. The live application test records an injected signal through the existing NVIDIA Broadcast endpoint in a separate process.

Device selection, setup, repair, restoration and explicit Windows Audio restarts use a compiled helper and Windows registry, COM-registration and service APIs. The app does not launch PowerShell for these operations. Existing version-1 endpoint backups remain readable. Configuration validates every affected endpoint before changing it, installs newly checked devices before restoring unchecked devices, and rolls back endpoint values and backups on failure. The completed device status survives translation passes; discovery times out with a retry option instead of remaining on Loading.

Remaining environmental validation includes elevated writes against physical capture devices, simultaneous physical capture devices, live voice calibration with spoken input, actual key delivery to other applications, external-editor launch and end-to-end ducking behavior in individual third-party applications. The compiled setup transaction is covered by in-memory failure fixtures, and the real helper/IPC has a read-only check. These validation limits do not hide or disable the settings.

Public builds contain generated notification tones/activation noise and built-in English strings. Optional external translation catalogs are excluded from the repository and CI release. No original executable, DLL, demo audio, user profile or recording is included.
